# grue — assistant rules

1. On ANY build request (local or CI), first ask Rich the version number, offering the current one (from src-tauri/tauri.conf.json) as the Enter-default. Never invent/increment versions. Versions live in exactly: src-tauri/tauri.conf.json, package.json, src-tauri/Cargo.toml — update all three only after Rich confirms.
2. Never commit or push unless Rich asks. Never close GitHub issues.
3. Build: `npx tauri build` from repo root; artifacts src-tauri/target/release (exe), .../bundle/nsis (installer). Defender exclusion + Dropbox-ignore already applied to target/.
4. Roadmap = GitHub issue #3 (Keep/Done checklists); tick Done boxes when features land.
5. Web grue lives at way.net/grue (server ~/public_html/grue; maps in grue/maps). The page grue/maps/index.php reads the folder and its subfolders on every visit, rewrites each folder's index.grue (the map of maps; subfolders are green boxes, .grue orange, .vue light orange) when the list changed, then redirects to the map in grue — no cron. After ANY upload to or removal from the maps folder, just load https://way.net/grue/maps/ once to refresh it. Local test copy: localhost:1420 (scratch server mirrors the live folder and does the same on /maps/). Unspecified changes: write localhost first, then way.net. Never upload the assets folder with `scp -r` (it resets the folder to private and blanks the app) — upload the files inside it, or run `chmod 755 ~/public_html/grue/assets` afterwards. The built index.html needs `data-cfasync="false"` on its module script tag (Cloudflare Rocket Loader breaks it otherwise); vite strips it, so re-add after each web build.
